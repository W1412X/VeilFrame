# ADR-0005：智能渲染（GOP 拼接）的风险与分期

- 状态：Proposed
- 日期：2026-11-20
- 关联：`first_design.md` 2.7（"智能渲染：按 GOP 对齐切分，含打码的 GOP 重编码，其余 `-c copy`，concat 合并——未打码区域零损失"）

## 背景

文档把"未打码区域零画质损失"作为核心卖点。这一点只在"未重编码的 GOP 原样拷贝"的前提下成立，而且拼接边界处有若干技术风险。

## 主要风险

1. **切点必须是 IDR 帧。** 只有从 IDR 开始切，拷贝段才能独立解码。如果源视频是 open-GOP（常见于部分相机和 B 帧设置），切点附近会出现解码花屏。
2. **音视频边界不同步。** 拷贝段和重编码段的起止 PTS 不一致，拼接处可能出现音画偏移或短暂静音。
3. **帧率与时间基不一致。** 变帧率（VFR）视频在 concat 时容易漂移，需要先转为 CFR。
4. **码率与参数不一致。** 重编码段与拷贝段的 profile、level、色彩空间不同，播放器兼容性会出问题。
5. **打码跨 GOP 的边界。** 一段打码可能跨越两个 GOP，边界那一组必须整体重编码，否则会漏打码。

## 建议的分期

- **第一期（M5）**：全量重编码。实现简单，结果可靠，先保证正确性。
- **第二期（M6）**：智能渲染。先在 IDR 对齐的源视频上实现，遇到 open-GOP 或 VFR 时自动回退到全量重编码，并在导出报告里提示（报告功能已删，改为导出日志）。

## 需要你确认

1. 第一期接受"全量重编码"作为导出方式，还是必须一开始就做智能渲染。
2. 遇到 open-GOP / VFR 时，回退全量重编码是否可以接受。
