# ADR-0003：交付分期

- 状态：Accepted（2026-11-20，用户选择一次性实现全部功能。M0–M6 保留为功能验收顺序，不再按阶段停工确认）
- 日期：2026-11-20
- 关联：`first_design.md` 全文

## 背景

文档描述的是终态：文本/图像/区域三类目标（语义对象已于 2026-11-20 从范围中删除）、五种图像匹配引擎、时序跟踪与融合、GPU 批处理与零拷贝、智能渲染、批量队列。一次性全部实现不可验收，也无法在本机完成端到端测试。因此需要切分里程碑，每个里程碑都能运行、能验证。

## 提议的分期

| 里程碑 | 范围 | 验收标准 |
|---|---|---|
| **M0 骨架** | Tauri 2 + React + TS 壳；Rust workspace（`core`、`media`、`vision`、`project`、`app`）；`.maskproj` 读写与 schema 校验；CI 本地脚本 | 能新建、保存、重新打开空项目；单元测试通过 |
| **M1 导入与复核** | ffprobe 元数据；抽取代理帧（长边 960）；时间轴与预览；手工建段、接受/否决、撤销重做 | 导入 10 分钟视频，时间轴与预览帧对齐；撤销重做覆盖所有段操作 |
| **M2 图像目标** | 模板特征缓存；SIFT + ratio test + RANSAC 单应；候选段生成；置信度公式 | 在基准集上固定台标检出率达到约定值（指标待定，见 ADR-0007） |
| **M3 跟踪与时序融合** | 光流补帧；FB 误差 + NCC 漂移检测；k 命中开段、m 丢失补洞；Kalman 平滑；场景切重置 | 段级 IoU 与漏检率达到约定值 |
| **M4 文本** | PP-OCRv5 ONNX 检测与识别；文本目标对缓存查询 | 文本目标在基准集上的漏检与误检达到约定值 |
| **M5 导出** | 多边形打码与外扩、羽化；全量重编码导出；批量队列 | 导出文件与预览一致；取消后无半成品文件 |
| **M6+ 性能与高级功能** | 智能渲染（ADR-0005）；GPU 批处理；零拷贝；LightGlue 精准档；自研 CUDA 核 | 以基准测试数据为准（ADR-0007） |

## 我的建议

第一期只做 **M0 + M1**，再决定是否进入 M2。M1 的价值是把数据模型、时间轴和撤销机制跑通，后面的检测引擎都挂在这上面，风险最低。

## 需要你确认

1. 第一期范围是否为 M0 + M1。
2. 文本、图像、区域三类目标，哪些在第一期必须有。我建议第一期只做"图像"类型。
3. 批量队列、报告（已删）、目标组导入导出，放在哪个里程碑。
