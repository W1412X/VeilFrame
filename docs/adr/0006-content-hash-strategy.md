# ADR-0006：视频内容哈希策略

- 状态：Proposed
- 日期：2026-11-20
- 关联：`first_design.md` 2.8（缓存键 = `视频内容哈希 + 引擎版本 + 参数指纹`），`.maskproj` 示例里的 `"sha1"` 字段

## 背景

感知缓存的键依赖视频内容哈希。对一个几十 GB 的视频做完整 SHA-1，在一台普通机器上会花费数分钟，而且每次打开项目都要重算，体验很差。

## 备选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 完整哈希 | 对整个文件求 SHA-256 | 正确性最强，可用于去重 | 慢，每次打开都要重算（可缓存结果，但仍需首次计算） |
| B. 抽样哈希 | 文件大小 + 首尾各 64 MB + 固定数量的中间块，求 BLAKE3 | 很快；对同一文件稳定 | 两个内容不同但抽样一致的文件会误判为同一个（概率很低，但不为零） |
| C. 元数据指纹 | 文件大小 + 修改时间 + 路径 | 最快 | 文件被复制或移动后失效；修改时间可能变化而内容不变 |

## 我的建议

选 **B（抽样哈希，BLAKE3）**，并在 `.maskproj` 中同时记录文件大小和抽样方式版本号。缓存命中后再做一次快速校验（例如比对首帧的 pHash）。`.maskproj` 示例中的 `"sha1"` 字段改为 `"contentHash"`，并标明算法。

## 需要你确认

1. 是否接受抽样哈希。如果需要完整哈希，请说明原因（例如去重、合规审计）。
2. 哈希算法选 BLAKE3 还是 SHA-256。
