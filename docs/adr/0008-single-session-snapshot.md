# ADR-0008：单会话、快照驱动的 Tauri 外壳

- 状态：Accepted
- 日期：2026-11-21
- 关联：ADR-0001、ADR-0002、`docs/HANDOVER.md`

## 背景

最初的交接文档建议把扫描做成独立 CLI，由 Tauri 子进程调用，让窗口进程不依赖 OpenCV。但真正接入时，扫描结果、进度、取消和编辑状态都来自同一个 `vf-session::Session`，拆成子进程就要自己设计一套进程间协议、状态同步和临时文件约定。

## 决策

1. 桌面外壳只持有一个 `Session`，放在 `Mutex<Option<Session>>` 里。扫描期间把会话取出放到阻塞线程，结束后放回；导出只克隆项目快照，不占用会话锁。
2. 所有编辑命令都返回完整的 `Snapshot`（项目、项目路径、撤销/重做可用性、自动保存错误、扫描/导出状态）。前端不保留第二份可编辑数据，只渲染快照和少量纯 UI 状态（当前时间、选中项、对话框）。
3. 扫描与导出都在 Tauri 进程的 `spawn_blocking` 线程里执行，通过 `vf-scan-progress`、`vf-export-progress` 事件推送进度，用 `AtomicBool` 取消。
4. 扫描在代理分辨率（长边 ≤ 960）上完成，四角坐标按比例映射回原视频；导出用 ffmpeg 全量重编码。

## 理由

- 状态只有一份，撤销/重做、自动保存、取消都不需要跨进程协调。
- 批处理和编辑器复用同一套 `vf-session`，行为一致。
- 前端从示例数据迁移到真实后端时，删除了 `app/src/domain/editor.ts`，避免两份编辑逻辑漂移。

## 代价

- Tauri 外壳直接链接 OpenCV 与 OCR 依赖，安装包因此变大，CI 需要为三个平台准备 OpenCV（见 release 工作流）。
- 扫描和导出期间编辑器只能读不能改（界面上表现为忙状态）；批量队列用独立会话绕开这个限制。
- 浏览器里直接打开 Vite 页面没有后端，命令会抛 `NotDesktopError`，只用于界面调试。

## 备选方案

- **独立 CLI + 子进程**：窗口轻量，但需要额外的 IPC、进度解析、项目文件锁和取消协议，第一期收益不足。
- **前端持有编辑状态**：与自动保存、撤销语义冲突，且无法保证 Rust 与 TS 行为一致，已否决。
